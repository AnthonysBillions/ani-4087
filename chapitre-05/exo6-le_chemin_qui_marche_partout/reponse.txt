Ce qui a change : Le code de rendu est le même dans les deux lancements ; ce qui change, c'est le dossier courant du processus. Un chemin relatif est relatif à ce dossier-là, pas au dossier du fichier source ni à celui de l'exécutable. Depuis le dossier du projet, murs/beton.png existe. Depuis Build/Bin/Debug-Windows/MaSalle/, il n'existe pas. Le journal s'écrit lui aussi sous le dossier d'où je lance : le second lancement a son propre logs/app.log, loin de la racine du projet.

Ce que LocateResource essaie : <A_RELIRE_DANS_NkPath.h : recopier l'ordre de recherche du commentaire de LocateResource, et vérifier avec le code>. Le principe attendu : le chemin tel quel depuis le dossier courant, puis des dossiers relatifs à l'exécutable, puis, sur un appareil comme Android, les ressources du paquet. La fonction rend une chaîne vide si rien ne convient, d'où le test avant Load. Rappel : le commentaire dit ce que quelqu'un a voulu écrire, le code ce qu'il a écrit ; en cas de désaccord, le code a raison.
